# 用 AI 把截图变成账单（分享导入）

思路：不在这款 App 里做 OCR/语音，而是用你已有的 AI App（DeepSeek / 豆包 / 通义）把消费截图整理成 CSV，
再从**系统分享面板**直接分享到「家庭记账本」，一次性导入。

## 一、固定格式（唯一契约）

App 只认这一种表头，第一行必须是：

```csv
日期,类型,金额,分类,归属,备注
2026-11-02,支出,28.50,餐饮,家庭,好想来零食-零食
2026-11-02,支出,15.00,交通,家庭,滴滴出行-打车
2026-11-03,支出,199.00,工作,个人,hostdare-服务器续费
```

| 列 | 规则 |
|---|---|
| 日期 | `YYYY-MM-DD` |
| 类型 | `支出` 或 `收入` |
| 金额 | 纯数字，两位小数，**不带 ¥ 和千分位** |
| 分类 | 只能从下面列表选一个 |
| 归属 | `家庭` / `个人` / `往来`（资金往来不算消费） |
| 备注 | 商户+商品，20 字以内，**不要带逗号** |

可用分类：`餐饮 交通 购物 居家 医疗 教育 娱乐 人情 宠物 旅行 其他 通讯 保险 工作`

## 二、AI 智能体提示词（直接粘贴）

在 DeepSeek 建一个智能体，系统提示词填：

```
你是记账助手。用户会发来消费截图（支付成功页、订单页、小票照片）。
你的任务是把它整理成 CSV 表格，只输出 CSV，不要任何解释文字。

表头固定为：日期,类型,金额,分类,归属,备注

规则：
- 日期：YYYY-MM-DD。截图没有日期就用今天
- 类型：只能是「支出」或「收入」
- 金额：纯数字，两位小数，不带 ¥ 和千分位。用实付金额，不要用商品原价
- 分类：只能从这些里选一个
  餐饮 交通 购物 居家 医疗 教育 娱乐 人情 宠物 旅行 其他 通讯 保险 工作
- 归属：家庭 或 个人。日用品/食材/家庭聚餐/孩子用品=家庭；
  个人服饰/护肤/娱乐/话费/游戏=个人；判断不了写「待定」
- 备注：商户名+商品，最多 20 字，**不要带逗号**

一个订单有多件商品时，只记一条，金额用订单总额，不要拆行。
看不清的字段留空，绝对不要猜金额。

示例输出：
日期,类型,金额,分类,归属,备注
2026-11-02,支出,28.50,餐饮,家庭,好想来零食便利店-零食
```

## 三、操作流程

```
① 截图（支付成功页 / 订单页 / 小票）
② 发到 DeepSeek 智能体 → 得到 CSV
③ 点「分享」→ 选择「家庭记账本」
④ App 弹出预览：每条都能改金额/分类/归属，也能删
⑤ 确认导入
```

## 四、导入前一定会预览

AI 识别可能出错（金额看错、漏掉运费），所以 App **不会直接入库**：
预览页会把每条列出来，金额、分类、归属都能改，可以删掉不要的，再确认。

导入后按「日期+金额+分类+备注」生成指纹去重，同一份 CSV 重复导入不会产生重复账目。

## 五、常见错误

| 提示 | 原因 |
|---|---|
| 表格格式不对：没找到「日期」和「金额」两列 | 表头不是固定格式，或 AI 加了解释文字 |
| 没有解析出任何记录 | 只有表头没有数据行，或金额列不是纯数字 |
| 分类只能用：xxx | 用了列表外的分类名，改一下即可 |

## 六、实现说明

- Android 侧：`MainActivity.kt` 注册 `ACTION_SEND`，用 `ContentResolver` 把分享进来的文件
  复制到应用私有缓存，再通过 MethodChannel（`family_ledger/share`）交给 Dart。
  **没有用第三方分享插件**——它们会把 `text/csv` 当成文本，把「文件路径字符串」当内容传进来，服务端必然解析失败。
- 后端：`POST /api/v1/imports/preview` 只解析不入库；`POST /api/v1/imports/confirm` 才写库。
